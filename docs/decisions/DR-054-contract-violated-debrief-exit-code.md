# Decision Record DR-054 — `rezidnt debrief` exits 3, not 0, for a contract-violated run

**Date:** 2026-07-25
**Status:** ACCEPTED (owner, 2026-07-25).
**Amends:** [DR-004](DR-004-exit-code-table.md)'s exit-code table. Exit 3 — "substrate fault, including daemon-side refusals" — gains one further trigger: a folded `run.contract.violated` record. No invariant text touched. Mints NO invariant, NO subject, NO field, NO trait method, NO dep (the DR-053 §Decision 5 ledger form) — this is a CLI projection change over a fact the DR-050 set already ratified, not a taxonomy change, so no `/subject` is owed. Adds a §20 index row.

## Context

**1. Today's computation.** `bins/rezidnt/src/main.rs::debrief` computes the exit class as a cascade: `3` if `report.alarms` is non-empty OR any gate verdict is `inconclusive`; else `5` if any gate verdict is `fail`; else `0`. The same function separately binds `contract_violated` off the folded graph to drive the JSON `contract_violated` object and the human `CONTRACT VIOLATED (…)` block — but that binding is **never read by the `code` computation**. A run whose gates all passed and whose recorded contract was independently violated exits **0**.

**2. What the withdrawn fact is.** `run.contract.violated` v1 (`spec/ontology.md`, "### DR-050 set") is the durable record that a substrate adapter refused a run's live stream because the recorded transcript contract its mapped facts rest on was falsified. The set's own text names its reason for existing: consumer (3), the DR-048 slice-C collator, exists so that turn-1 totals published as RUN totals "cannot silently win a trial." Absent this ruling, that same silent-win shape reaches the `debrief` exit code — a surface the unbuilt collator was never meant to be the sole guard for.

**3. The argument for 3.** DR-004 built exit 3 as the "neither trusted nor coerced" class: an `integrity.alarm` earns it because a *recorded verdict* can no longer be trusted (replay diverged from the log). `run.contract.violated` is the same species of claim one axis over — not the verdict but the *accounting the run reports*, because the stream it was computed from was withdrawn. I3 means neither withdrawal is retracted; the withdrawal is itself a durable fact. DR-004's own text already scoped exit 3 to "substrate fault, including daemon-side refusals," which an adapter's `ContractViolated` refusal textually is. Today a CI caller gating on `debrief`'s exit code alone sees a premise-broken run as clean.

**4. Why 3 and not 5, or a new code.** *(Alternative — exit 5, the gate-fail class — REJECTED.)* DR-004 fixes 5 as "a recorded verdict says fail": a gate ran and returned a negative answer. A contract violation is not a gate verdict; no gate ran against it and none said fail. Coding it 5 would let a caller "fix" a contract violation by making gates pass — the miscoercion I6 forbids. *(Alternative — mint a dedicated exit code — REJECTED.)* Exit 3 already means "cannot be trusted or certified"; a contract violation is a member of that class, not a new one. A second cannot-certify code fragments a 0-vs-not-0 CI contract for no information a caller needs at that layer — the `--json` report already carries the discriminating detail.

**5. Ordering.** `contract_violated.is_some()` joins the **existing exit-3 disjunction**, so a run that is both contract-violated and gate-failing exits **3**, not **5**. "We cannot certify this run at all" dominates "one of its gates failed," mirroring the standing rule that `inconclusive` already dominates `fail` in the same disjunction. *(Alternative — let a recorded `fail` dominate, as the more actionable signal — REJECTED: a gate's `fail` verdict is itself computed over inputs the withdrawn stream may have fed; ranking it above the premise objection would certify a specific negative answer while refusing to certify the accounting beside it. Refusal-to-certify outranks a certified answer in either direction.)*

**6. What this does NOT do — named, not silently inherited as settled.** `contract_refused` is read in exactly one place, `drive_run`'s stream-loop short-circuit, and nowhere else. A contract-violated run still reaps, still chunks its capture into `artifact.captured`, still runs `pre_merge`, and **can still merge**. Whether a withdrawn stream premise should block a merge is UNRULED — no DR or ontology bullet says — and stays open for its own record; this one rules the CLI's exit-code projection only. Nor does it widen any projection: `RunRow`/`SubRow` still render a violated run's turn-1 totals unmarked, deferred to DR-048 slice-C scoping (owner, 2026-07-25) and named here, not re-decided.

**7. Present reach.** `spec/ontology.md`'s 2026-07-25 wiring-truth-pass records the emitter as WIRED-BUT-UNREACHABLE on any live daemon path: `ContractViolated`'s sole construction site is `CodexAdapter::map_run_completed`, and the daemon's `SUPPORTED_HARNESSES` refuses `"codex"`. This ruling is correct and dischargeable now, but its exit-3 trigger is reachable in practice only against a directly-seeded log (as the CLI oracle drives it) until codex reaches the `AgentSubstrate` seam. Prospective, and honestly so.

## Decision

1. **`debrief`'s exit-3 disjunction gains a third condition: a folded `run.contract.violated` record.** `code = 3` if `!report.alarms.is_empty() || has_inconclusive || contract_violated.is_some()`; else `5` if `has_fail`; else `0`. No new exit code is minted.
2. **Ordering:** contract-violated joins the FIRST branch of the cascade, so it dominates a recorded `fail` (exit 3, not 5) when both are present on one run.
3. **Scope, ruled explicitly:** the exit-code projection only. It does not block a merge, does not gate `pre_merge`, and does not widen `RunRow`/`SubRow`. Both residuals are named in §Context 6 as open, not settled here.

- **Risk register.** RETIRES the silent-clean-exit risk implicit in the DR-050 set's consumer-(3) rationale, at the `debrief` exit-code surface specifically (the collator itself is still unbuilt and still owed). ADDS none. NAMES two residuals, unfixed by design: (a) a contract-violated run can still merge; (b) the board still renders a violated run's totals unmarked.
- **Test/criterion honesty, plain words.** `bins/rezidnt/tests/dr050_contract_violated_debrief.rs`'s shared runner asserts exit 0 for every case, including its seeded VIOLATED runs — its own header discloses that this is a STATUS-QUO pin on an open question, not a ruling, and that it "deliberately goes red the day a DR changes the exit class, and should then be updated to follow the DR, never quietly deleted." **This is that DR.** The clean-run case keeps asserting exit 0 (DR-004 law, untouched); the violated-run cases must assert exit 3. A red test here is the ruling's judge arriving, not a regression, and the implementer must not read it as one. This record weakens no test and lowers no bar.
