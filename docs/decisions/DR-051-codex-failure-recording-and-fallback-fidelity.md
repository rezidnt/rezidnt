## Context

**1. The recording.** On the owner's direction, a second real codex-cli 0.145.0 transcript was captured via `codex exec --json --skip-git-repo-check -m definitely-not-a-real-model-xyz "reply with the single word: hi"` (stdin closed) — `spec/fixtures/transcripts/codex_exec_v0.145.0_turn_failed.jsonl`, thread `019f99d8-…`. Its terminal line is `turn.failed` carrying `error.message`; it contains **no `turn.completed` line at all**. The oracle pinned the contract in `crates/rezidnt-run/tests/codex_adapter_turn_failed.rs` (five tests); the implementer mapped `turn.failed → agent.completed{status:"error"}` to close it, carrying the harness's reason verbatim — commit `4ceccb7` on the same lane as slice A (`worktree-agent-ab4e17a54fbbdb421`; `cargo test -p rezidnt-run`: 145 passed, clippy/fmt clean), **pending its own `/gauntlet` and merge — not yet on `main`.**

**2. What the recording settles, and what it does not.** DR-050 recorded two positions: the implementer read `turn.completed` as the harness positively asserting termination; the auditor, narrowing, held it asserts only *termination* while `status` is a separate *outcome* claim the codex line doesn't carry — and that claude-code's split `type:"result"`/`subtype`+`is_error` proves the two are distinguishable in principle. The failing recording resolves the empirical question: a turn that ends badly emits `turn.failed`, never `turn.completed`. So `turn.completed` does mean what the implementer read it to mean, **for this recorded version**. The auditor's underlying structural observation is not thereby wrong — codex genuinely carries outcome as one undifferentiated event type where claude-code uses two channels, and that asymmetry is real and worth remembering. What closes is narrower: for codex-cli 0.145.x, that thinner channel does not in fact produce a mismapped success. The refutation is scoped to `TESTED_CODEX_VERSIONS = &[(0,145)]` (`crates/rezidnt-run/src/adapter.rs:46`); it is a property of two transcripts at one version, not a claim about codex's wire contract in general. Widening that list to a future minor without a fresh recording would silently re-open the exact question this closes — DR-050's Decision 1 (the currently-unreachable version gate) is the mechanism that prevents that, once wired to a live call site.

**3. The "clean residual" was not clean.** DR-050's Context called the daemon's exit-status fallback (`bins/rezidentd/src/runs.rs:1702-1723`, keyed on `completed_id.is_none()`) a clean cover for the unmapped-failure gap. It does fire, and it does terminate the run honestly as `status:"error"` — but the literal it publishes hardcodes `cost:{total_usd:0.0, input_tokens:0, output_tokens:0}` with no `error` key at all (`runs.rs:1703-1709`). The harness's own failure reason — now proven to exist and ride `turn.failed.error.message` — is **discarded, not carried**. This is a real gap, not a residual to wave past.

**4. The bonus finding: absent usage, not zero usage.** `turn.failed` carries **no `usage` object at all** — a failed codex turn reports zero token *accounting*, not zero tokens. The adapter's `Completion::into_fact`/`reported_usage` already omit the token keys entirely when `usage` is absent, rather than zeroing them (`adapter.rs:195-200`, `254-287`; the doc there is explicit: "Optional keys are omitted, never emitted as null — a null key would be a present claim of an absent value (DR-012 declared-vs-absent)"). The reducer this feeds is `Option<u64>` end-to-end: `crates/rezidnt-state/src/lib.rs:788-789` calls `.as_u64()` on `payload.cost.input_tokens`/`output_tokens`, which is `None` on an absent key, never a coerced `0`. Named plainly: without this, DR-048 slice C's collator would have scored a failed codex candidate as a **free run** — a zero-cost win against every candidate that actually spent tokens and lost. Pinned by `turn_failed_reports_usage_as_absence_not_zero`.

**5. Where absence stops surviving: the `debrief` CLI edge.** `bins/rezidnt/src/main.rs:2272-2282` (the `rezidnt debrief <run>` command — the surface `/debrief`, the done-gate, reports through) builds its `cost` object directly from the folded `Option<f64>`/`Option<u64>` fields: `serde_json::json!({"total_usd": r.total_usd, "input_tokens": r.input_tokens, "output_tokens": r.output_tokens})`. Serde's default `Option` serialization turns `None` into an explicit JSON `null` — the reducer's honest absence survives the fold and dies exactly at the report a human or the auditor reads, becoming a **present claim of an absent value**, the precise thing `into_fact`'s own doc (citing DR-012) forbids. This is **not codex-dormant**: `AgentRunState` derives `Default`, so `total_usd`/`input_tokens`/`output_tokens` are `None` until an `agent.completed` fact folds — `rezidnt debrief` carries no guard against being called before a run completes, on any harness, today, on `main`. The auditor surfaced this while reviewing the codex fallback fix; its reach is broader than codex.

## Decision

1. **DR-050 §Context finding 3 is SETTLED BY RECORDING, scoped to codex-cli 0.145.x.** The codex `turn.completed → status:"success"` mapping is confirmed; the auditor's mismapped-failure branch is REFUTED for `TESTED_CODEX_VERSIONS = &[(0,145)]` only — not generalized to any other codex-cli version, past or future. The auditor's structural dissent (one undifferentiated event type vs. claude-code's two channels) stands as accurate description, not as an open risk for this version window. *(Alternative — treat the recording as settling codex's contract in general — REJECTED: one version's transcript proves one version's behavior; DR-050's own Decision 1 names the mechanism, once wired, that must gate any future widening.)*

2. **DR-050 §Consequences risk item 5 is STRUCK.** "A mismapped codex success would score as pass under I6, with no recorded transcript proving the mapping wrong" is refuted by the recording named above, for codex-cli 0.145.x. Risk to any version outside `TESTED_CODEX_VERSIONS` is already covered by DR-050's risk item 1 (no live version gating today) — it is not a new, separate risk.

3. **DR-050's "clean residual" claim is CORRECTED, not struck.** The daemon fallback (`runs.rs:1702-1723`) fires and terminates honestly, but discards the failure reason. This is folded into DR-050 §Decision 2(c) as amended below — it does not stand alone as a new decision, since (c) already targets this exact literal.

4. **DR-050 §Decision 2(c) is SHARPENED: the cross-crate pin must compare FAILURE payloads, not a key-set over success payloads.** As originally drafted, (c) asked for "a cross-crate test" pinning the daemon's fallback literal against `Completion::into_fact`'s shape. The auditor showed a key-set-equality test over the two SUCCESS payloads would pass today while `runs.rs:1706` keeps emitting `{"input_tokens":0,"output_tokens":0}` for a run whose harness reported no usage at all — same keys, opposite meaning: `0` says "measured, and it was nothing," the fallback's `0` would say that about a run that was never measured. That is a semantic contradiction the original criterion could not catch. Amended text for slice B entry criterion (c): *the second `agent.completed` fallback literal must be pinned against `Completion::into_fact`'s FAILURE-shaped output (a run that terminated with no usage reported) as well as its shape, and must carry whatever error text the dying child's last stream line reported rather than emitting a bare zeroed literal — a passing key-set-only test is not sufficient evidence this criterion is met.*

5. **A new DR-048 slice-C entry criterion is ADDED: absence discipline must survive to every consumer of `AgentRunState`'s cost fields, not just the reducer.** `rezidnt debrief`'s existing cost block (`bins/rezidnt/src/main.rs:2272-2282`) emits explicit `null` for an unfolded cost field today, independent of codex — this is a present, reachable defect on `main`, not a dormant one. Slice C's collator/leaderboard reads the same `Option<f64>`/`Option<u64>` fields; if it renders them the same way, it inherits the same defect at a higher-stakes surface (a leaderboard, not a debug report). Fix at both sites in the same pass: omit absent keys rather than serializing `None` as `null`, mirroring `Completion::into_fact`'s convention. *(Alternative — treat `main.rs`'s bug as out-of-scope, filed separately from Trials — REJECTED: it is the same absence-discipline question this record is otherwise about, discovered by the same review pass, and DR-048 slice C is about to build a second, larger consumer of the exact fields that leak; fixing it once, here, is cheaper than fixing it twice.)*
