# Decision Record DR-059 — Pin the real diff: an additive `patch` ref, and a mime that finally tells the truth

**Date:** 2026-07-26
**Status:** ACCEPTED 2026-07-26.
**Amends:** [DR-057](DR-057-diff-review-mcp-resource.md) §Decision 1 — `diff_view`'s response gains a second optional ref, `patch: CasRef | null`, alongside the existing `diff` field, which is UNTOUCHED. Follows, does not amend, [DR-043](DR-043-secret-scan-content-ref.md)'s sibling-ref shape. Touches `spec/ontology.md`'s `diff.ready`/`diff.merged` v1 payload blocks and mime note — an amendment pointer is owed there, applied by the warden `/subject` session this record authorizes, not stamped here. Mints NO invariant, NO subject, NO trait method, NO dep — see Ledger for the FIELD limb, which is authorized, not minted, by design. Adds a §20 index row.

## Context

**The finding, from a real end-to-end run (2026-07-26, WSL daemon + Windows client, every link verified): `open_project` → worktree allocated → files edited → `diff.ready` folded → `diff_view` returned a `CasRef` → badged `cas_read` returned content, verbatim:**

```
# rezidnt diff summary v1
M README.md blake3:64e4c611…
M main.rs blake3:c2e424b6…
```

A file-status list with content hashes. No `+`/`-` lines, no context, no removals. Not reviewable — it cannot answer "is this change correct," which is the entire point of Review (DR-038 §Decision 4/5).

**Every premise checked against the tree, not assumed:**

1. `gates::summarize_worktree` (`bins/rezidentd/src/gates.rs:418-431`) calls `git_diff_summary`, which renders exactly the `<letter>\t<path>` lines above, and pins them with `cas.put(&bytes, "text/x-diff")`. The mime is FALSE — confirmed by reading the function; it has never produced diff-formatted bytes. `cas_read`'s mime gate (DR-058) judges the CALLER's claimed mime, which is exactly this stored string echoed back through `diff_view` — so the lie is load-bearing on the client's trust, not cosmetic.
2. Two native verifiers depend on the summary's CURRENT format: `DiffScope` and `ForbiddenPath` (`crates/rezidnt-gate/src/lib.rs:404-480`) both read `input.refs["diff"]` and parse it as `<letter>\t<path>` lines via `touched_paths`. Confirmed. They are BINDING `pre_merge` inputs and must not break. `resolve_ref` (`:211-227`), which both call, does not inspect mime at all — it is not merely mime-string-agnostic in its branches, it never reads the field — so a mime correction cannot touch them regardless.
3. `summarize_worktree_content` → `git_added_content` (`:498-538`, DR-043) pins per-file ADDED content only — no removals, no context, skips deleted files entirely. Confirmed also not a diff. DR-043 is the governing precedent: it added a sibling ref (`refs["content"]`, gate-side only) and left `summarize_worktree`'s existing summary untouched, explicitly, for exactly the reason this record follows.
4. The SAME `CasRef` produced by one `summarize_worktree()` call rides both the event payload (`diff.ready.diff` at `runs.rs:2148`) and the gate's `refs["diff"]` map (`:2163`), and is threaded verbatim into `merge_worktree`, which republishes it onto `diff.merged.diff` (`gates.rs:653-666`). Confirmed: one blob, three consumers (two facts, one gate). A second, independent site produces the identical format under the identical false mime: `crates/rezidnt-adapters/git/src/lib.rs::summarize_to_cas` (`:1610-1621`), the watcher's continuous emitter. Any fix must cover both sites or the watcher-sourced `diff.ready` keeps lying after the gate-time one stops.

**This is the fourth instance in this arc of a record or doc-comment describing something the tree does not have** — DR-049's ledger (corrected by DR-052), DR-057's "additive" `last_diff` widening, DR-058's "shape unchanged" `cas_read` badge — **and the only one that reached a user-facing surface.** The other three were caught by oracle boards and audits before merge. This one survived two oracle boards and two `/debrief` rounds on DR-057/058 and was found only by running the golden path end to end and reading the bytes `cas_read` actually returned.

## Decision

1. **Mint (authorize) an additive-optional sibling field `patch?: CasRef` on `diff.ready` v1 and `diff.merged` v1**, carrying the real `git diff` unified-format bytes for the change the existing `diff` field summarizes. Both emission sites gain it TOGETHER — `gates::summarize_worktree` (the gate-time pin) and `crates/rezidnt-adapters/git/src/lib.rs::summarize_to_cas` (the watcher's continuous emitter) — never one without the other, matching the existing `diff` field's own two-emitter symmetry (`spec/ontology.md:330-334`). `v` stays 1 on both subjects; existing fixtures lacking the key stay valid unchanged. **This field is AUTHORIZED here, NOT MINTED** — landing it in `spec/ontology.md` is a warden `/subject` call, per house practice ([DR-043](DR-043-secret-scan-content-ref.md) §Consequences: "a warden question, not settled here"). No implementer work lands the key before that session runs.
2. **`diff_view`'s response gains `patch: CasRef | null`** alongside its existing `diff` field, with the SAME null-when-unfolded semantics DR-057 §Decision 1 already rules for `diff` — never a fabricated empty patch. The derived-state fold gains the matching slot. Whether that widening is additive or breaking on the SERIALIZED axis (goldens, reader suites) — the exact question DR-057/DR-058 got wrong twice — is the landing slice's obligation to check and disclose, not assumed free by this record.
3. **`refs["diff"]` — the gate's native-verifier input map — is UNCHANGED.** Same key, same path-status-summary bytes, same two consumers. The `patch` bytes are NOT wired into the gate refs map by this record; a future native wanting real diff content is its own record, following DR-043's own pattern of one ref per one honest need.
4. **The summary's mime is corrected from the false `text/x-diff` to `text/x-diff-summary`** — stays `text/*` (so `cas_read`'s `is_text_mime` gate, and DR-058's mime-is-the-caller's-claim finding, are both satisfied without code change), and matches `spec/ontology.md:329`'s own "DEFAULT, not load-bearing" framing of this mime. Verified additive-SAFE on behavior: no code anywhere branches on the exact string (`is_text_mime` checks only the `text/` prefix; `resolve_ref` ignores mime entirely). NOT free: at least four golden fixtures (`s2_diff_ready`, `dr057_diff_ref_retained`, and their DR-058 derivatives) and one test assertion (`dr057_partial_diff_ref_folds_none.rs:156`) pin the literal string and must be recut — disclosed here, not hidden.
5. **The new `patch` ref's mime is `text/x-diff`** — the label the whole stack already trusted, finally attached to bytes that are actually diff-formatted.
6. **Size is REAFFIRMED, not re-litigated.** `cas_read`'s existing `MAX_CAS_READ_BYTES_DEFAULT` (256 KiB) bound and its refuse-don't-truncate behavior (DR-057/058) is the accepted answer for an oversized real diff — no paging is invented here. The operator cockpit's Review panel already renders `cas.too_large` honestly with the size visible; nothing further is owed by this record.

**Rejected, recorded:**
- **Widen `git_diff_summary` in place** to emit real diff bytes under the existing `diff` field — REJECTED: breaks `DiffScope`/`ForbiddenPath`, both BINDING `pre_merge` inputs that parse the current line shape; a real unified diff has neither that shape nor a guaranteed one-line-per-file structure.
- **Reuse the DR-043 `content` ref for review** — REJECTED: added-content only, no removals, no surrounding context. A pure-deletion file shows nothing; a modified file shows only its after-state with no way to see what changed. Not a diff by any reading, and DR-043 built it for a different, narrower need (a scanner, not a reviewer).
- **Put diff bytes on the fabric directly** — REJECTED on I2; restated only so Decision 1's CAS-ref shape is not mistaken for a live question.

**Strongest counterargument, recorded.** Correcting only the mime, with no new ref, is cheaper, and a status-plus-content-hash list is already useful triage signal — an operator can at least see WHICH files changed without seeing HOW. Rejected on the owner's own e2e verdict, written against exactly this output: "Not reviewable." A file list cannot answer "is this change correct," and that question is the entire reason DR-038 §Decision 4/5 requires Review as a governed capability. The cheaper fix corrects a label without closing the gap the label's correction was supposed to serve.
